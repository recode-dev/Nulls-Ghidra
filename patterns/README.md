# patterns/ — перенос якорей на новую сборку без старого бинаря

`offsig.py` умеет то же, но требует **обе** сборки на диске. Файл паттернов заменяет
старую сборку: он несёт токенизированные окна функций, поэтому новую версию можно
проверять в CI, не таща предыдущий 18-МБ exec.

## Формат `patterns/<версия>.json.gz`

- `intern` — словарь токенов, собранный **только из паттернов**: индекс → текст
  инструкции, где иммедиаты замаскированы (`adrp x8, #0x1a000` → `adrp x8, #0x…`),
  а шумовые инструкции (`bti`, `pacibsp`, `nop`, `hint`, `autibsp`, `xpaclri`) выброшены.
- `entries[]` — `{id, name, rva, head, span}`: `id` уникален (`name`, а при дублях имени —
  `name@rva`), `rva` — начало функции, `head` — смещение от начала функции до первой
  значащей инструкции (выброшенный пролог), `span` — до 96 токенов начиная с `head`.
- `k=24` — окно поиска, `ext=96` — окно проверки.

## Прогон

```
python3 tools/nbscan.py <exec_старой> out/offsets_<старой>_all
python3 tools/patgen.py --bin <exec_старой> --table out/offsets_<старой>_all.json \
        --version <старая> --out patterns/<старая>.json.gz
python3 tools/patrun.py --bin <exec_новой> --patterns patterns/<старая>.json.gz \
        --starts out/offsets_<новой>_all.json --out resolved_<новая>.csv \
        --report resolved_<новая>.md --require anchors.txt --min-rate 0.6
```

`patgen` по умолчанию берёт только именованные адреса (`--all` — включая `sub_*`) и
выбрасывает шаблоны (`--keep-templates` — вернуть). Шаблон — окно, которое в самой
сборке встречается больше одного раза; это почти всегда строковые геттеры `ref_*`, у
которых различается только замаскированный иммедиат, поэтому ассемблером их различить
нельзя. На 69.252 шаблонов 2 395 из 8 216 — и именно они давали всю неоднозначность.

## Статусы

| статус | смысл |
|---|---|
| `matched` | один кандидат, 96-токеновая проверка совпала |
| `weak` | найден, но проверка хвоста не совпала (изменился код после пролога) |
| `resolved` | кандидатов было несколько, выбран по соседним `matched` — угадайка |
| `ambiguous` | несколько кандидатов, соседей не хватило |
| `missing` | окно не найдено: код изменился, нужен `offsig` со старым бинарём или руки |

`--min-rate` считает `matched+weak` от общего числа. `--require <файл>` требует, чтобы
перечисленные якоря (по имени или `id`) оказались в `matched`/`weak`; отсутствующий файл
игнорируется, так что гейт можно включать постепенно.

## Замеры на реальных сборках

| прогон | результат |
|---|---|
| самонаведение `69.252 → 69.252` | 5 549 matched + 17 resolved = **100%**, drift 0 у всех |
| `68.279 → 69.252` (Null's поверх официальной) | matched 4 475, weak 386, resolved 15, ambiguous 1, missing 547 → **найдено 89.8%** |
| `69.252 → 68.279` | matched 4 460, weak 388, missing 707 → найдено 87.1% |

Точность по независимому источнику — берём только якоря, у которых имя уникально в обеих
сборках, а истиной считаем адрес, который целевая сборка дала этому имени **сама**:

| статус | попадание |
|---|---|
| `matched` | **2 057 / 2 076 = 99.1%** |
| `weak` | 172 / 183 = 94.0% |
| `resolved` | 4 / 7 |
| `missing` | 0 / 189 (ничего не выдумано) |

Размер файла ≈ 0.7 МБ на ~5.5k якорей (gzip). Без фильтра шаблонов было бы ~13 МБ и 35%
попаданий.

## Грабли (обе стоили точности)

1. **Адрес считается из потока токенов, а не как `start + 4*j`.** Шумовые инструкции из
   потока выброшены, поэтому линейная арифметика уезжала на 4 байта за каждую выброшенную
   инструкцию (`pacibsp`, `bti`, `nop`), а на функциях с длинным прологом — на десятки
   байт. Исправлено в `offsig.Code`: регион несёт `addrs[]`, окно ищется `bisect`-ом,
   `scan` отдаёт настоящий адрес токена, а `head` в паттерне держит смещение
   «начало функции → первая значащая инструкция», чтобы `new_rva` был началом функции, а
   не её серединой. Точность `matched` до фикса — 32.6%, после — 99.1%.
2. **`--starts` — предпочтение, а не фильтр.** Список стартов строится по прологам и видит
   не всё, поэтому фильтр по нему ронял результат с 91% до 35%. Сейчас он включается
   только для разрешения неоднозначности.
